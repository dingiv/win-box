# 01 核显直通「代码 43」排障全记录

> 结论先行：**代码 43 的解法是「对齐社区已跑通的整配方」，而不是找单一魔法开关。**
> 生效的四处改动：① 仓库成对 ROM ② 核显挂专属 PCIe 根端口 ③ `topoext` ④ `x-vga=on`。

## 1. 症状与背景

> **关于本文**：这是当时的**实录**（含走过的弯路与证据），不是使用说明。
> 命令已规整为本仓库的形式（`winbox …`）；接口以 `docs/interfaces/` 为准。

把 Ryzen 7 9800X3D 的核显（`1002:13c0`）直通给 Windows 11 客户机后：

- 设备管理器：`AMD Radeon(TM) Graphics` 黄色感叹号，**代码 43**
  （`CM_PROB_FAILED_POST_START`，"Windows 已将其停止，因为该设备报告了问题"）
- 任务管理器里没有 GPU；桌面实际由 **Microsoft 基本显示适配器**驱动
- 物理显示器能出画（那是 OVMF 的 GOP 初始化 + 基本显示驱动的结果，**不代表 AMD 驱动正常**）
  —— 这个误判让我们多花了不少时间：**"屏幕亮了 ≠ 驱动起来了"**，判据必须看
  `ConfigManagerErrorCode` 和任务管理器的 GPU。

客机里暴露出的其他线索（都指向驱动初始化失败）：

```
RadeonSoftware.exe 在 vulkan-1.dll 崩溃（异常 0xc0000409）
amduw23g-* 组件损坏事件
事件 219：驱动 \Driver\WUDFRd 加载失败，Device: ROOT\DISPLAY\0000（IDD）
某次 BasicDisplay 上还出现过 STATUS_GRAPHICS_NOT_POST_DEVICE_DRIVER (0xC01E0438)
```

## 2. 被逐一排除的假设（矩阵）

| # | 假设 | 试验 | 结果 |
|---|---|---|---|
| 1 | ROM 未挂上 | HMP 读 ROM BAR 尺寸、`info mtree` | ROM 正常（VGA 64KB / 音频 128KB）✗ |
| 2 | 缺 GOP（UEFI 需要 VBIOS+GOP） | 音频功能挂通用 GOP ROM | 已具备 ✗ |
| 3 | Secure Boot 拦未签名 ROM | 关闭 SB + 无密钥 OVMF_VARS | 无影响 ✗ |
| 4 | 宿主 framebuffer 占着核显显存 | `initcall_blacklist=sysfb_init video=efifb:off` | 已解决 ✗ |
| 5 | 宿主机 amdgpu 抢绑核显 | 拉黑 + 不进 initramfs + vfio-pci ids + softdep | 已解决 ✗ |
| 6 | ROM 要"盖章"成 1002:13c0 | 自盖章版 GOP | 反而更差 ✗（通用版/CPU 专属版才对） |
| 7 | GOP 挂音频功能能在 OVMF 下救 43 | 通用版 GOP 挂音频 | 否 ✗ |
| 8 | 自家 VFCT dump 最匹配 | 换成自家 dump | 否（社区文档明确：**ASUS 上用自家 dump 必 43**）✗ |
| 9 | 设备需要"真复位" | `amdgpu` 复位轮回（MODE2 reset） | 否（复位是必要的卫生条件，但不是 43 的解）✗ |
| 10 | `x-vga` 与 IDD 抢显示角色 | 关掉 x-vga | 否 ✗（`0xC01E0438` 是 BasicDisplay 的附带现象） |
| 11 | 驱动安装被污染 | 删驱动包 + 重新下载离线包 | 否（驱动包本来就只有一套且是最新）✗ |
| 12 | 显存/UMA 大小不匹配 | 宿主 amdgpu 报 `VRAM: 2048M`，客机 WMI 也报 2GB | 一致，排除 ✗ |

## 3. 最终生效的配置（四处，缺一不可）

依据：**https://panther.kapsi.fi/posts/2026-10-12_gpu_passthrough**
（作者硬件与我们几乎相同：**ASUS TUF B850M-PLUS II + Ryzen 9900X/9950X + Win11 + OVMF**，
且记录了同样的"自家 BIOS 提取 ROM → 必然 43"的经历）

### ① ROM 用仓库**成对**文件（而不是自家 dump）

| 挂载点 | 文件 | sha256 前缀 | 大小 |
|---|---|---|---|
| `0d:00.0`（VGA） | `vbios_ref_9800x3d.bin`（仓库 `vbios_9800x3d.bin`） | `cb766e1d7b9161b9` | 44544 B |
| `0d:00.1`（音频） | `AMDGopDriver_9800x3d_plain.rom`（仓库 `AMDGopDriver_9800x3d.rom`，**未盖章**） | `8b8d24841a332c8b` | 83456 B |

要点：GOP **贴在音频功能上**，且用仓库提供的 CPU 专属/通用版本；
仓库作者原话——"VBIOS 与 GOP 来自同代不同型号都行，但别用自己主板 BIOS 提取的"。
（我们实测：自家 VFCT dump → 43；仓库通用 GOP + 自家 dump → 43；仓库成对 → 成功。）

### ② 核显挂**专属 PCIe 根端口**（不是根总线）

```
<controller type='pci' index='15' model='pcie-root-port'>
  <target chassis='15' port='0x0'/>
</controller>
... 直通设备地址:
  bus='0x0f' slot='0x00' function='0x0' multifunction='on'   ← VGA
  bus='0x0f' slot='0x00' function='0x1'                      ← 音频（同槽多功能）
```

两个社区配方（isc30 的 Proxmox 指南 `pcie=1`、上面那篇博客的 `-device pcie-root-port`）
**都挂根端口**，只有我们原来挂在 `pcie.0` 根总线上。

### ③ CPU 暴露 `topoext`

```xml
<feature policy='require' name='topoext'/>
```

LG 客户端启动时一直在警告：*"The host CPU has hardware threads but the guest is not aware of them …
For AMD CPUs, enable the `topoext` CPU feature"*。

### ④ `x-vga=on`

```xml
<qemu:override>
  <qemu:device alias='hostdev0'>
    <qemu:frontend>
      <qemu:property name='x-vga' type='bool' value='true'/>
```

## 5. 经验总结

1. **"画面出来了"不等于"驱动起来了"**：必须看错误码/任务管理器 GPU。
2. **优先抄整配方**：核显直通涉及固件、ROM、拓扑、CPU 特性、驱动多方交互，
   社区能跑通的配置是"多点同时满足"的解，逐个变量试会拖很久。
3. **同型号硬件+同症状的案例价值最高**（那篇博客与我们逐条对得上）。
4. 排查时把"证据"沉淀成脚本（`winbox adopt && sudo winbox gpu-attach` 一键对齐），
   并保留 A/B 能力（`winbox gpu-attach --rom <文件>` 可切换两份 VBIOS）。
