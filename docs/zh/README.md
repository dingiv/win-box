# 中文实录（docs/zh）

这里是**当时的实战记录**，不是使用说明。区别很重要：

| | 在哪 | 是什么 |
| --- | --- | --- |
| **契约** | `docs/interfaces/`、`docs/calltrees/` | 工具**应该**怎么做（接口、失败语义、链路） |
| **实录** | 本目录 | **当时**怎么做成的：走过哪些弯路、看到什么证据、最后哪几处对齐了才通 |

实录里保留了大量失败路线与原始证据（`dmesg` 片段、错误码、指纹），因为"为什么不是那样做"
和"怎么做"同样有价值——尤其在这个领域，很多结论是**反直觉**的。

> 命令形式已规整为本仓库的 `winbox …`；但叙述里仍会出现"第 3 步""四要素"这类当时的上下文，
> 它们是记录的一部分，不做平滑处理。

## 旧脚本编号 → 今天的命令

本仓库把工作区里那批"按时间顺序排的脚本"重构成了按阶段划分的命令。
如果你在实录里看到旧编号，对照如下：

| 旧脚本 | 今天的命令 |

| `02` | `winbox vm-create` |

| `05` `07` `23` `24` | `winbox gpu-attach`（+ `winbox rom patch`） |
| `06` `21` | `sudo winbox lg-shmem`（权限双闸） |

| `12` | `winbox evidence` |
| `13` | `winbox vm mode <test\|inspect\|both\|lg>` |
| `14` | `winbox vm snapshot-save [名字]` |
